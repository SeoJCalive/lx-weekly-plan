# 주간업무 계획 작성·검토 플랫폼 프로젝트 정의서

- 문서 상태: 초안 2판 (설계 결정 합의 완료, LX 담당 과장님 확인 전)
- 작성일: 2026-11-19
- 대상 조직: 한국국토정보공사(LX) 기획혁신본부
- 근거 자료: `.ovis/기획혁신본부_11월2주_업무계획_00-…hwpx`, `.ovis/공사_본사부설기관_부서_직제-…hwpx`, 의뢰자 구두 설명
- 1차 검토 목표일: 2026-11-22(일)

이 문서는 개발에 들어가기 전에 무엇을 만들지 합의하기 위해 쓴다. 조직과 검토 절차의 일부는 아직 과장님께 확인받지 않았으므로, 확인되지 않은 내용은 "가정"으로 표시하고 9장에 모았다. 구조를 먼저 만들고 확인 결과에 따라 고친다.

## 1. 배경

기획혁신본부는 매주 주간업무 계획을 한글(hwp) 파일로 작성해 취합한다. 파일을 고치고, 주고받고, 단계별로 검토와 수정 지시를 받는 과정이 모두 파일 왕복으로 이뤄져 번거롭다.

- 각 처의 담당자가 업무 항목을 작성한다.
- 단계별 책임자가 내용을 확인하고 수정을 지시한다.
- 제출 마감은 목요일이다.
- 새 주차를 작성할 때 지난주의 "금주 계획"을 "전주 실적" 위치로 옮기고 새 계획을 쓴다.
- 최종 결정자가 배포해야 구성원이 완성본을 받는다.

## 2. 목표

한글 파일 왕복을 없애고, 웹 페이지 하나에서 작성, 검토, 취합, 배포, 출력을 처리한다. 화면은 사용자의 역할에 필요한 기능만 보여 조작을 단순하게 유지한다.

- 작성과 검토를 웹 페이지에서 한다.
- 진행 상태를 현황판에서 한눈에 본다.
- 결과물은 기존 한글 양식과 거의 같은 모습으로 화면에 보이고 hwpx로 출력된다.

이 결과물은 시연용이다. 실제 운영하지 않으므로 확장 대비보다 핵심 기능이 끝까지 동작하는 데 집중한다.

## 3. 대상 조직과 문서 구조

### 3.1 조직

직제 문서 기준으로 본부 → 실 → 처의 3단계다.

| 본부 | 실 | 처 |
|---|---|---|
| 기획혁신본부 | 기획조정실 | 기획처 |
| | | 예산법무처 |
| | AI디지털전략실 | AI혁신처 |
| | | 정보보안운영처 |
| | (없음) | 경영성과처 |

- 경영성과처는 실 없이 본부 직속이다.
- 팀은 직제와 양식에 단위로 나오지 않는다. "팀장" 직함과 "예산팀 전원" 표기로만 확인된다.
- 플랫폼은 팀을 조직 단위로 만들지 않고, "팀장"은 개인의 직함으로만 다룬다.

### 3.2 주간업무 계획 양식

- 표지: 제목("기획혁신본부 주간업무 계획 <11.9.~11.13.>"), 작성일, 로고.
- 본문: `[실_처]` 섹션이 조직 순서대로 이어진다. 실이 없는 처는 `[처]`로 표기한다.
- 섹션 상단: 2열 표. 왼쪽 "전주 실적(기간)" 아래 "□ 완료업무", 오른쪽 "금주 계획(기간)" 아래 "□ 주간업무".
- 섹션 하단: 1열 표 "< 계 속 업 무 >".
- 기획처는 오른쪽 소제목이 "□ 월간업무"로 적혀 있다.
- 용지는 A4 세로이며 샘플은 6쪽이다.

### 3.3 업무 항목

작성의 최소 단위는 업무 항목 한 건이다.

- 번호와 제목.
- "○ (내용)" 본문.
- "*", "**" 부가 설명(일시/장소, 참석자, 대상 등).
- 표(선택). 병합 셀과 합계 수식을 포함할 수 있다.
- "(업무담당자)" 표기. 한 명 이상이며, "예산팀 전원" 같은 자유 표기도 있다.

한 항목에 여러 팀의 사람이 함께 들어가고, 같은 사람이 항목마다 다른 사람과 묶인다. 그래서 항목을 특정 팀이나 개인의 칸으로 고정하지 않는다.

### 3.4 글자 서식

샘플의 글자 서식은 위치에 따라 고정돼 있다.

- 항목 제목은 굵게 12pt, 내용은 11pt, 부가 설명은 9pt다.
- 예외는 한 곳이다. 기획처 항목 제목의 한 단어가 파란색이다.
- 밑줄과 기울임은 쓰이지 않는다.
- 합계는 숫자가 아니라 한글의 수식 필드로 저장돼 있다.

## 4. 사용자와 역할

| 역할 | 대상(가정) | 할 수 있는 일 | 검토 단위 |
|---|---|---|---|
| 작성자 | 처 소속 구성원 | 항목 생성, 본인 할당, 작성, 중간 저장, 검토 요청, 회수 | 해당 없음 |
| 처 검토자 | 처장 | 승인, 수정 요청, 처 취합본 상신 | 항목별 |
| 실 검토자 | 실장 | 승인, 수정 요청, 실 취합본 상신 | 처 섹션별 |
| 최종 결정자 | 본부장 | 최종 승인, 수정 요청, 마감 설정, 배포 | 처 섹션별 |

- 각 역할의 화면에는 그 역할의 기능만 노출한다.
- 실 검토자와 최종 결정자는 처 섹션 단위로 승인하되, 수정 요청을 보낼 때 항목을 지목한다.
- 검토자도 본인이 담당자인 항목은 작성자로서 작성할 수 있다.

## 5. 기능 요구사항

### 5.1 접속

- 이름과 사번을 입력해 접속한다. 비밀번호와 SSO는 구현하지 않는다.
- 처장, 실장, 본부장은 사번으로 미리 등록한다. 명단을 받지 못하면 시연용 가상 계정으로 등록한다.
- 계정과 문서 내용의 사람 이름은 모두 가상 이름이다. 시연 사이트를 외부에 공개하므로 샘플 문서의 실명을 화면과 출력물에 쓰지 않는다. 대응표는 13장에 둔다.
- 그 밖의 구성원은 처음 접속할 때 소속 처와 직급을 본인이 입력한다.
- 조직(본부, 실, 처)은 미리 등록해 둔다.
- 접속 화면에 계정 목록을 두고 클릭 한 번으로 계정을 전환할 수 있다.

### 5.2 작성

- 작성 화면은 칸별 입력과 한글 양식 미리보기로 구성한다. 입력 칸은 제목, 내용, 부가 설명, 표, 담당자다.
- 작성자는 소속 처 섹션에 항목을 만들 수 있다.
- 작성자는 기존 항목에 스스로를 담당자로 할당하거나 해제할 수 있다.
- 한 항목에 여러 명이 할당될 수 있고, 할당된 사람은 그 항목을 수정할 수 있다.
- 한 사람이 항목을 편집하는 동안 다른 사람은 읽기만 한다. 편집 중 표시는 다른 사람에게만 보이며, 글 대신 항목 테두리 색과 편집자 이름의 머리글자로 나타낸다. 편집하는 본인에게는 표시하지 않는다.
- 저장 상태(저장됨, 저장 안 된 변경 있음)는 글 대신 저장 버튼 옆의 작은 점으로 나타낸다.
- 담당자 표기는 할당된 사람의 이름과 직함으로 자동 구성하고, 직접 고쳐 쓸 수 있다.
- 항목 구분은 전주 실적(완료업무), 금주 계획(주간업무), 계속업무 세 가지다.
- 오른쪽 소제목 문구("□ 주간업무" 등)는 처별로 바꿀 수 있다.
- 항목 번호는 순서에 따라 자동으로 붙인다.
- 중간 저장을 할 수 있다.

### 5.3 글자 강조와 표

양식이 깨지지 않는 것이 가장 중요하다. 그래서 작성자가 고를 수 있는 서식을 샘플에 실제로 쓰인 범위로 제한한다.

- 글꼴과 글자 크기는 위치에 따라 고정이며 작성자가 바꿀 수 없다.
- 글자 강조는 굵게와 글자 색(파랑, 빨강) 두 가지만 허용한다.
- 강조는 작성자가 입력란에서 고른 글자에 적용한다. 적용한 강조는 입력란 안에서도 보인다.
- 강조 버튼은 편집할 수 있는 동안 항상 보이고, 버튼마다 적용될 모양(굵게, 파랑, 빨강)을 그대로 보여준다.
- 강조 버튼은 누르면 켜지고 다시 누르면 꺼지는 전환 버튼이다. 고른 글자 전체에 이미 적용된 강조는 그 버튼이 눌린 모양으로 보인다. 별도의 강조 해제 버튼은 두지 않는다.
- 문서에 자주 쓰는 특수 문자(○ · → 「」 ‘ □)와 줄 머리말 "○ (내용) "을 버튼으로 바로 넣을 수 있다. 이 버튼은 강조 버튼과 같은 줄에 둔다.
- 표는 행과 열의 추가와 삭제, 셀 병합, 가운데 정렬을 지원한다.
- 표의 합계 수식(SUM)을 지원한다. 화면에서는 자동으로 계산하고, hwpx에는 수식 필드로 내보낸다.

### 5.4 상태와 검토 흐름

| 상태 | 의미 | 바뀌는 시점 |
|---|---|---|
| 미작성 | 내용이 없다 | 항목 생성 직후 |
| 작성 중 | 저장된 내용이 있다 | 중간 저장 시 자동 반영 |
| 검토 요청 | 상급자의 검토를 기다린다 | 작성자가 검토 요청 시 |
| 수정 요청 | 상급자가 수정을 요구했다 | 검토자가 메시지와 함께 반려 시 |
| 승인 | 상급자가 승인했다 | 검토자가 승인 시 |

- 검토 요청을 하면 그 시점의 작성 버전이 고정된다.
- 검토 요청 뒤에 고치려면 작성자가 "회수"해 작성 중으로 되돌린 뒤 수정한다.
- 수정 요청 메시지는 해당 버전에 붙어 기록된다.
- 처 검토자는 처의 모든 항목이 승인 상태일 때 처 취합본을 상신할 수 있다.
- 실 검토자는 소속 처 섹션이 모두 승인 상태일 때 실 취합본을 상신할 수 있다.
- 검토 순서는 처 → 실 → 본부다. 실이 없는 처는 본부로 바로 간다.
- 검토자는 승인한 뒤에도 다시 수정 요청을 보낼 수 있다.
- 작성자는 승인된 항목도 수정해 다시 검토 요청할 수 있다(재상신).
- 실 검토자와 최종 결정자의 수정 요청은 처 섹션에 보내되, 고칠 항목을 지목한다.
- 작성자는 두 번째 제출부터 검토 요청에 수정 사유를 적을 수 있다. 수정 요청을 받지 않고 고쳐 올릴 때도 같다. 수정 사유는 선택 입력이며 해당 버전에 붙어 기록된다.

수정 요청과 수정 사유는 오간 자리에서 바로 보여야 한다.

- 수정 요청을 받은 항목은 작성 화면에서 색 띠로 둘러 강조한다.
- 그 항목 아래에 접었다 펼 수 있는 수정 요청 카드를 둔다. 카드에는 보낸 사람, 시각, 메시지가 나온다.
- 작성자가 적은 수정 사유는 검토자의 검토 화면에서 같은 자리에 수정 사유 카드로 보인다.
- 처 섹션 검토에서 온 수정 요청은 지목된 항목에 붙이고, 항목 검토에서 온 요청과 구분해 표시한다.

### 5.5 재상신 때 재검토 범위

승인된 내용이 수정되면 그 위 단계의 승인이 해제된다. 다만 다시 볼 범위는 바뀐 부분으로 좁힌다.

- 처 검토자는 고친 항목만 다시 승인한다.
- 실 검토자와 최종 결정자는 그 처 섹션만 다시 승인한다.
- 다시 검토할 때 바뀐 항목이 표시된다.
- 다른 처의 승인은 유지된다.

### 5.6 현황판

- 처 구성원은 처 안의 항목별 상태를 본다.
- 실 검토자와 최종 결정자는 처별, 실별 상태를 본다.
- 같은 단계의 단위끼리 서로의 상태를 볼 수 있다.
- 검토자는 현황판에서 승인과 수정 요청을 한다.
- 상태가 바뀌면 현황판에 바로 반영된다.

### 5.7 할 일 표시와 알림

- 접속하거나 계정을 전환하면 게시판이 처음 나온다. "내가 할 일"만 모은 별도 화면은 두지 않는다.
- 할 일은 메뉴 옆 숫자로 보인다. 작성 메뉴에는 내가 처리할 수정 요청 개수, 현황판 메뉴에는 내가 검토하거나 상신할 대상 개수를 붙인다.
- 개수가 0이면 숫자를 붙이지 않는다. 숫자에 설명 문구를 덧붙이지 않고 모양으로 알 수 있게 한다.
- 현황판은 내가 처리할 대상이 있는 처를 먼저 연다.
- 메일이나 메신저 알림은 보내지 않는다.

### 5.8 마감

- 기본 마감은 목요일이다.
- 최종 결정자가 마감 일시를 바꿀 수 있다.
- 마감이 지나도 작성과 제출을 막지 않는다. 마감 경과 여부만 표시한다.

### 5.9 주차 이월

- 최종 결정자가 배포하면 다음 주차가 자동으로 열린다.
- 최종 결정자는 배포 전에도 다음 주차를 수동으로 열 수 있다.
- 지난주의 "금주 계획" 항목은 새 주차의 "전주 실적"으로 그대로 복사된다.
- 계속업무 항목은 새 주차에 그대로 유지된다.
- 이월된 항목을 실제 결과에 맞게 고치는 것은 작성자가 한다. 완료 여부를 자동으로 판단하지 않는다.
- 제목과 표의 기간 표기는 주차에 맞춰 자동으로 채운다.
- 첫 주차는 샘플 문서를 한 번 변환해 초기 데이터로 넣는다. 업무담당자 칸의 실명은 글자 수가 같은 가상 이름으로 바꿔 넣고, 직함과 나머지 내용은 그대로 둔다.

### 5.10 배포와 게시판

- 최종 승인 뒤 최종 결정자가 배포를 실행해야 게시판에 게시된다.
- 배포된 문서를 수정해 다시 배포하면 기존 게시물을 덮어쓰지 않고 새 버전이 쌓인다.
- 게시물 제목은 양식 제목에 차수를 붙인다(예: "기획혁신본부 주간업무 계획 <11.9.~11.13.> 2차").
- 게시판에서는 버전 목록을 보고, 문서를 화면으로 보고, hwpx를 내려받는다.

### 5.11 기록과 통계

- 기록은 검토 요청, 수정 요청, 승인 시점의 버전만 남긴다. 중간 저장은 기록하지 않는다.
- 기록에는 시각, 사람, 내용, 수정 요청 메시지, 수정 사유가 들어간다.
- 기록 화면은 왼쪽에 단계 목록, 오른쪽에 고른 단계 하나의 내용을 둔다. 모든 단계를 아래로 펼쳐 놓지 않는다.
- 왼쪽 목록은 두 단이다. 위는 처 섹션의 단계(상신, 실 검토자와 최종 결정자의 승인과 수정 요청), 아래는 항목별 단계(제출, 수정 요청, 재제출, 승인)다.
- 오른쪽에는 고른 단계의 제출 내용, 수정 요청 메시지 또는 수정 사유, 직전 버전과 달라진 부분, 그 항목의 양식 미리보기가 나온다.
- 왼쪽 목록과 오른쪽 내용은 따로 스크롤된다.
- 항목 단위 기록과 처 섹션 단위 기록은 구분해 표시한다.
- 작성 화면의 각 항목과 처 검토자의 검토 화면에서 그 항목의 기록만 가운데 팝업으로 열 수 있다. 팝업은 좁은 단계 목록과 고른 단계의 내용으로 구성하고 양식 미리보기는 넣지 않는다.
- 팝업에서 기록 화면으로 이동하면 같은 항목의 같은 단계가 선택된 상태로 열린다.
- 통계는 처별 수정 횟수, 수정 요청 횟수, 마감 준수 여부를 보여준다. 기록 화면 안의 별도 탭에 둔다.

### 5.12 출력

- 전체 문서를 hwpx로 출력한다.
- 처 단위, 실 단위로 본인 소속 범위만 따로 출력할 수 있다.
- 출력은 내려받기 표시가 붙은 버튼 하나로 두고, 누르면 출력 범위(전체 주차, 소속 실, 소속 처)를 고르는 목록이 펼쳐진다. 설명 문구를 덧붙이지 않고 버튼 모양으로 파일이 내려받아진다는 것을 알 수 있게 한다.
- hwpx는 샘플 문서를 틀로 삼아 내용만 바꿔 넣는 방식으로 만든다. 글꼴, 표 선, 여백, 로고가 원본 그대로 유지된다.
- 출력물은 기존 양식의 요소를 하나도 빼지 않는다. 표지, 로고, 섹션 표, 소제목, 항목 내 표, 병합 셀, 합계 수식을 모두 포함한다.
- 화면 미리보기는 표 모양, 열 너비, 글자 크기와 굵기를 한글과 맞춘다. 쪽 나눔 위치는 맞추지 않으며 hwpx를 열어 확인한다.

### 5.13 화면 구성

| 메뉴 | 내용 |
|---|---|
| 게시판 | 배포된 문서의 버전 목록, 화면 보기, hwpx 내려받기. 접속 직후 기본 화면 |
| 작성 | 내 처의 섹션, 칸별 입력과 미리보기, 수정 요청 카드, 항목 기록 팝업. 메뉴에 내가 처리할 수정 요청 개수 |
| 현황판 | 상태 보기, 검토자의 승인과 수정 요청. 메뉴에 내가 검토하거나 상신할 대상 개수 |
| 기록 | 단계 목록과 고른 단계의 내용·양식 미리보기, 통계 탭 |

### 5.14 화면 디자인

사용감이 가장 중요하다. 디자인은 꾸밈보다 배치와 구조를 먼저 정하고, 그 위에 양식을 입힌다.

- 방향은 흑백의 모던한 브루탈리즘이다. 선은 너무 강하지 않게 쓴다.
- 바탕은 검정, 흰색, 회색 단계로 구성한다.
- 색은 의미를 전하는 곳에 쓴다. 상태 표시, 주요 동작 버튼, 마감 경과 같은 알림이 해당한다.
- 테두리는 가는 선으로 구획을 나누는 데 쓰고, 굵은 검정 테두리는 쓰지 않는다.
- 그림자, 그라데이션, 둥근 모서리, 장식 요소는 쓰지 않는다.
- 위계는 글자 크기와 굵기, 여백, 격자 배치로 만든다.
- 다섯 가지 상태는 상태마다 다른 색으로 구분하고, 상태 이름을 글자로 함께 표시한다.
- 처 섹션이 검토 단계 중 어디까지 왔는지는 처 → 실 → 본부의 단계 진행 막대로 보여준다. 칸의 색이 그 단계의 상태다. 실이 없는 처는 두 칸이다.
- 되돌리기 어려운 동작(다음 주차 열기, 배포, 내 담당 해제)은 작성·검토 같은 일상 동작과 떨어진 자리에 두고, 누르면 확인창을 거친다. 다음 주차 열기와 내 담당 해제는 테두리만 있는 약한 모양으로 둔다. 배포는 최종 결정자가 그 자리에서 할 주된 일이므로 주요 동작 모양을 유지한다.
- 화면을 이해시키려고 설명 문구를 덧붙이지 않는다. 기능과 상태는 버튼 모양, 눌림 상태, 색, 자리로 알 수 있게 한다(2026-11-22 사용자 요청).
- 같은 상태는 모든 화면에서 같은 색을 쓴다.
- 수정 요청 카드와 수정 사유 카드는 같은 모양으로 만들고 색과 문구로 구분한다.
- 목록에서 고른 줄은 한눈에 구분되게 표시한다.
- 한글 양식 미리보기는 이 디자인을 적용하지 않고 원본 양식의 모습을 그대로 보여준다.

### 5.15 시연 데이터와 시연 대본

시연은 몇 주째 쓰고 있는 상태에서 시작해야 현황판, 게시판, 기록, 통계를 빈 화면 없이 보여줄 수 있다. 초기 상태는 출력 비교에 계속 쓰이므로 그대로 두고, 시연 상태를 만드는 명령을 따로 둔다.

- 시연 상태는 `bun run demo`로 만든다. 데이터를 초기 상태로 되돌린 뒤 시연 상태를 다시 만들며, 몇 번 실행해도 같은 결과가 나온다.
- 시연 상태는 값을 직접 써 넣지 않고, 플랫폼의 작성·검토·승인·배포 기능을 시각만 바꿔 가며 차례로 실행해 만든다.
- 지난 주차는 2개다(11.9.~11.13., 11.16.~11.20.). 둘 다 배포돼 게시판에 있고, 첫 주차는 2차까지 있다.
- 지난 주차의 기록에는 항목 수정 요청, 수정 사유가 붙은 재제출, 실 검토자의 처 섹션 수정 요청이 들어 있다. 마감을 지킨 처와 넘긴 처가 섞여 있다.
- 이번 주차는 11.23.~11.27.이다. AI디지털전략실의 세 처는 최종 승인까지 끝났다. 기획처는 실 검토자 승인까지 끝났고, 예산법무처는 항목 하나가 처 검토자의 수정 요청을 받은 상태다.
- 실 검토자는 소속 처가 모두 승인돼야 상신할 수 있으므로(5.4절), 기획처는 예산법무처가 승인될 때까지 최종 결정자에게 올라가지 않은 채로 기다린다. 이번 주차의 기록은 모두 지난 주차를 배포한 11.20.(금) 오후의 시각이다. 시연에서 누르는 동작은 실제 시각으로 기록되므로, 시연 데이터의 시각이 그보다 앞서야 기록의 순서가 맞는다.
- 주차마다 새로 들어가는 금주 계획 항목은 양식의 문체를 따른 가상의 업무다.
- 시연 대본은 `docs/시연_대본.md`에 둔다. 장면마다 접속 계정, 누를 것, 보여야 할 것을 적는다. 장면은 여섯 개 안쪽이고 시연 상태에서 바로 시작한다.
- 대본의 장면은 수정 요청 받은 항목의 재제출, 처 검토자 승인, 실 검토자와 최종 결정자의 승인과 배포, 게시판과 hwpx, 배포 뒤 수정과 2차 게시, 기록과 통계다.

### 5.16 사용성 보완 (2026-11-22)

처음 쓰는 사람이 시연 흐름을 따라갈 때 멈칫한 자리를 고친다. 모두 설명 문구가 아니라 자리, 모양, 동작으로 해결한다. 항목마다 따로 빼거나 방향을 바꿀 수 있게 한 항목씩 구현한다.

1. 수정 요청 뒤 입력: 수정 요청을 받은 항목을 열면 요청 카드 바로 아래의 입력칸이 1280×720 화면에서도 스크롤 없이 보인다. 강조·특수 문자 도구줄은 입력란마다 반복하지 않고, 편집 영역에 하나만 두어 지금 커서가 있는 입력란에 적용한다.
2. 표 범위 선택: 표에서 셀을 끌거나 Shift를 누른 채 눌러 범위를 고른다. 고른 범위는 음영으로 보이고, 병합과 합계는 고른 범위에 적용된다. 합계는 고른 범위의 바로 오른쪽 또는 아래 셀에 들어가고, 결과 셀은 다른 테두리로 보인다. 범위를 글자로 입력하는 칸은 두지 않는다.
3. 항목 추가 자리: 항목 추가 버튼은 고른 분류 목록의 끝에 둔다. 누르면 그 목록에 새 항목이 생기고 제목 입력란에 커서가 간다.
4. 기록으로 가는 제목: 현황판 제출본에서 눌러 기록을 여는 업무 제목은 누를 수 있는 모양(마우스를 올리면 밑줄, 기록 표시)으로 보인다.
5. 통계의 주차 바꾸기: 기록 화면에서 주차를 바꿔도 보던 탭(기록/통계)과 고른 처는 유지되고 데이터만 바뀜다.
6. 고른 탭: 고른 탭은 마우스를 올려도 어두운 바탕과 흰 글자를 유지한다.
7. 게시판 안내: 배포 완료 안내는 방금 배포한 차수의 목록 줄에만 표시하고, 다른 차수를 고르면 문서 머리에는 고른 차수의 정보만 남는다.
8. 게시판 고정 영역: 긴 문서를 내려도 차수 목록과 고른 차수의 제목·내려받기 버튼은 화면에 남는다. 문서만 스크롤된다.
9. 다음 주차 열기 뒤: 현황판에서 다음 주차를 열면 현황판에 머물고, 작업 주차만 새 주차로 바뀐다.

## 6. 설계 원칙

시연용이므로 확장 대비는 최소로 한다. 과장님 확인 결과에 따라 바뀔 가능성이 높은 두 가지만 코드가 아니라 데이터로 둔다.

- 조직(본부, 실, 처)과 그 순서.
- 검토 단계와 각 단계의 검토자.

작성 단위는 업무 항목으로 고정한다. 이 구조는 실제 문서에서 나온 것이다.

## 7. 범위

### 7.1 포함

- 주간업무 계획의 작성, 검토, 취합, 배포, 게시, 출력.
- 기획혁신본부 5개 처.

### 7.2 제외

- 비밀번호, SSO 등 실제 인증.
- 조직 관리 화면(조직은 사전 등록).
- 월간 업무계획 흐름(9장 확인 후 반영 여부 결정).
- 기획혁신본부 외 다른 본부.
- 기존 hwp/hwpx 파일을 읽어 들이는 가져오기 기능(첫 주차 샘플은 일회성 변환).
- 메일, 메신저 알림.
- 양식 디자인 자체를 플랫폼에서 바꾸는 기능.
- 실제 운영을 위한 서버 설치, 데이터 보존, 장애 대응.

## 8. 제약

- 내부망 PC에서 사용하는 것을 전제로 한다.
- 출력 형식은 hwpx다.
- 양식의 어떤 요소도 임의로 빼지 않는다.
- 양식이 깨지지 않는 것을 기능 추가보다 우선한다.

## 9. 미확정 사항

아래는 과장님께 확인할 내용이다. 괄호 안은 이 문서가 채택한 가정이다.

### 9.1 구조에 영향을 주는 것

1. 검토는 처 → 실 → 본부 순서인가? (가정: 맞음)
2. 각 단계의 검토자는 처장, 실장, 본부장인가, 별도의 취합 담당자인가? (가정: 각 단계의 장)
3. 처장에게 가기 전에 팀장이 따로 확인하는 절차가 있는가? (가정: 없음)
4. 경영성과처는 본부장에게 바로 올리는가? (가정: 바로 올림)
5. 항목은 담당자가 각자 쓰는가, 처마다 한 명이 모아 쓰는가? (가정: 담당자가 직접 씀)
6. 담당자가 여러 명인 항목은 누가 쓰는가? (가정: 담당자 누구나 수정 가능)
7. 새 주차에서 "금주 계획"을 "전주 실적"으로 그대로 옮기는가, 고쳐 쓰는가? 계속업무는 유지하는가? (가정: 그대로 복사 후 작성자가 고쳐 씀, 계속업무 유지)
8. 기획처의 "□ 월간업무" 소제목은 무슨 의미인가? 별도의 월간 업무계획 문서가 있는가? 있다면 샘플을 받을 수 있는가? (가정: 범위 제외, 소제목 문구만 처별 변경 가능)

### 9.2 세부에 영향을 주는 것

9. 마감은 하나인가, 단계마다 다른가? (가정: 하나)
10. 배포는 본부장이 직접 하는가, 실무자가 대신하는가? (가정: 본부장)
11. 배포 후 수정해 다시 배포하는 일이 실제로 있는가? 수정본 제목은 어떻게 구분하는가? (가정: 있음, 차수 표기)
12. 배포된 문서는 본부 내부만 보는가? (가정: 본부 내부만)
13. 작성 중인 다른 처의 내용을 서로 볼 수 있는가? (가정: 상태만 보이고 내용은 배포 후 열람)
14. 처, 실 단위로만 따로 출력하는 경우가 있는가? (가정: 있음)
15. 본부 전체 인원 명단(이름, 사번, 소속 처, 직급)을 받을 수 있는가? 어렵다면 처별 인원수는? (가정: 검토자만 사전 등록, 나머지는 본인 입력)

## 10. 기술 구성

- 언어: 화면과 서버 모두 TypeScript.
- 서버와 데이터베이스: Bun(내장 웹 서버와 SQLite). 데이터는 파일 하나에 저장한다.
- 화면: React.
- hwpx 생성: 압축 파일 안의 XML을 직접 고쳐서 만든다. 별도 변환 프로그램에 의존하지 않는다.
- 실행 위치: 개발 워크스테이션. 내부망 PC로 옮길지는 과장님 확인 뒤에 정한다.

## 11. 완료 기준

1. 샘플 주차를 플랫폼에 넣고 hwpx로 출력하면 한글에서 원본과 눈으로 구별하기 어렵다. 업무담당자 칸의 이름 글자만 다르고, 줄 수와 칸 크기와 쪽 나눔은 원본과 같다.
2. 항목 하나가 작성 → 검토 요청 → 수정 요청 → 재제출 → 처장·실장·본부장 승인 → 배포까지 끝난다.
3. 배포 뒤 항목을 고치면 승인이 풀리고, 다시 배포하면 게시판에 2차가 쌓인다.
4. 화면의 배치와 구조가 아래 사용감 검토 항목을 통과한다.

사용감 검토 항목은 화면이 생기거나 바뀔 때마다 실제 화면을 띄워 확인한다.

- 역할마다 지금 해야 할 일이 메뉴의 숫자로 바로 보인다.
- 자주 하는 동작(작성, 저장, 검토 요청, 승인, 수정 요청)이 적은 단계로 끝난다.
- 관련 있는 정보와 동작이 가까이 모여 있고, 화면을 오가지 않아도 된다.
- 현재 위치, 현재 상태, 다음에 할 수 있는 동작이 항상 보인다.
- 그 역할에 필요 없는 기능이 화면에 나오지 않는다.
- 기록은 목록에서 고른 단계만 보여주고, 단계가 늘어도 화면이 아래로 길어지지 않는다.
- 5.14절의 디자인 방향을 지키면서 글자가 잘 읽히고 구획이 분명하다.

출력물은 윈도우 PC의 한글에서 직접 열어 쪽별로 캡처하고 원본과 비교해 확인한다.
