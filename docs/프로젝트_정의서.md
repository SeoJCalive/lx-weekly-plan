# 주간업무 계획 작성·검토 플랫폼 프로젝트 정의서

- 문서 상태: 초안 2판 (설계 결정 합의 완료, LX 담당 과장님 확인 전)
- 작성일: 2026-11-19
- 대상 조직: 한국국토정보공사(LX) 기획혁신본부
- 근거 자료: `.ovis/기획혁신본부_11월2주_업무계획_00-…hwpx`, `.ovis/공사_본사부설기관_부서_직제-…hwpx`, 의뢰자 구두 설명
- 1차 검토 목표일: 2026-11-22(일)

이 문서는 개발에 들어가기 전에 무엇을 만들지 합의하기 위해 쓴다. 조직과 검토 절차의 일부는 아직 과장님께 확인받지 않았으므로, 확인되지 않은 내용은 "가정"으로 표시하고 9장에 모았다. 구조를 먼저 만들고 확인 결과에 따라 고친다.

## 1. 배경

기획혁신본부는 매주 주간업무 계획을 한글(hwp) 파일로 작성해 취합한다. 파일을 고치고, 주고받고, 단계별로 검토와 수정 지시를 받는 과정이 모두 파일 왕복으로 이뤄져 번거롭다.

- 각 처의 담당자가 업무 항목을 작성한다.
- 단계별 책임자가 내용을 확인하고 수정을 지시한다.
- 제출 마감은 목요일이다.
- 새 주차를 작성할 때 지난주의 "금주 계획"을 "전주 실적" 위치로 옮기고 새 계획을 쓴다.
- 최종 결정자가 배포해야 구성원이 완성본을 받는다.

## 2. 목표

한글 파일 왕복을 없애고, 웹 페이지 하나에서 작성, 검토, 취합, 배포, 출력을 처리한다. 화면은 사용자의 역할에 필요한 기능만 보여 조작을 단순하게 유지한다.

- 작성과 검토를 웹 페이지에서 한다.
- 진행 상태를 현황판에서 한눈에 본다.
- 결과물은 기존 한글 양식과 거의 같은 모습으로 화면에 보이고 hwpx로 출력된다.

이 결과물은 시연용이다. 실제 운영하지 않으므로 확장 대비보다 핵심 기능이 끝까지 동작하는 데 집중한다.

## 3. 대상 조직과 문서 구조

### 3.1 조직

직제 문서 기준으로 본부 → 실 → 처의 3단계다.

| 본부 | 실 | 처 |
|---|---|---|
| 기획혁신본부 | 기획조정실 | 기획처 |
| | | 예산법무처 |
| | AI디지털전략실 | AI혁신처 |
| | | 정보보안운영처 |
| | (없음) | 경영성과처 |

- 경영성과처는 실 없이 본부 직속이다.
- 팀은 직제와 양식에 단위로 나오지 않는다. "팀장" 직함과 "예산팀 전원" 표기로만 확인된다.
- 플랫폼은 팀을 조직 단위로 만들지 않고, "팀장"은 개인의 직함으로만 다룬다.

### 3.2 주간업무 계획 양식

- 표지: 제목("기획혁신본부 주간업무 계획 <11.9.~11.13.>"), 작성일, 로고.
- 본문: `[실_처]` 섹션이 조직 순서대로 이어진다. 실이 없는 처는 `[처]`로 표기한다.
- 섹션 상단: 2열 표. 왼쪽 "전주 실적(기간)" 아래 "□ 완료업무", 오른쪽 "금주 계획(기간)" 아래 "□ 주간업무".
- 섹션 하단: 1열 표 "< 계 속 업 무 >".
- 기획처는 오른쪽 소제목이 "□ 월간업무"로 적혀 있다.
- 용지는 A4 세로이며 샘플은 6쪽이다.

### 3.3 업무 항목

작성의 최소 단위는 업무 항목 한 건이다.

- 번호와 제목.
- "○ (내용)" 본문.
- "*", "**" 부가 설명(일시/장소, 참석자, 대상 등).
- 표(선택). 병합 셀과 합계 수식을 포함할 수 있다.
- "(업무담당자)" 표기. 한 명 이상이며, "예산팀 전원" 같은 자유 표기도 있다.

한 항목에 여러 팀의 사람이 함께 들어가고, 같은 사람이 항목마다 다른 사람과 묶인다. 그래서 항목을 특정 팀이나 개인의 칸으로 고정하지 않는다.

### 3.4 글자 서식

샘플의 글자 서식은 위치에 따라 고정돼 있다.

- 항목 제목은 굵게 12pt, 내용은 11pt, 부가 설명은 9pt다.
- 예외는 한 곳이다. 기획처 항목 제목의 한 단어가 파란색이다.
- 밑줄과 기울임은 쓰이지 않는다.
- 합계는 숫자가 아니라 한글의 수식 필드로 저장돼 있다.

## 4. 사용자와 역할

| 역할 | 대상(가정) | 할 수 있는 일 | 검토 단위 |
|---|---|---|---|
| 작성자 | 처 소속 구성원 | 항목 생성, 본인 할당, 작성, 중간 저장, 검토 요청, 회수 | 해당 없음 |
| 처 검토자 | 처장 | 승인, 수정 요청, 처 취합본 상신 | 항목별 |
| 실 검토자 | 실장 | 승인, 수정 요청, 실 취합본 상신 | 처 섹션별 |
| 최종 결정자 | 본부장 | 최종 승인, 수정 요청, 마감 설정, 배포 | 처 섹션별 |

- 각 역할의 화면에는 그 역할의 기능만 노출한다.
- 실 검토자와 최종 결정자는 처 섹션 단위로 승인하되, 수정 요청을 보낼 때 항목을 지목한다.
- 검토자도 본인이 담당자인 항목은 작성자로서 작성할 수 있다.

## 5. 기능 요구사항

### 5.1 접속

- 이름과 사번을 입력해 접속한다. 비밀번호와 SSO는 구현하지 않는다.
- 처장, 실장, 본부장은 사번으로 미리 등록한다. 명단을 받지 못하면 시연용 가상 계정으로 등록한다.
- 그 밖의 구성원은 처음 접속할 때 소속 처와 직급을 본인이 입력한다.
- 조직(본부, 실, 처)은 미리 등록해 둔다.
- 접속 화면에 계정 목록을 두고 클릭 한 번으로 계정을 전환할 수 있다.

### 5.2 작성

- 작성 화면은 칸별 입력과 한글 양식 미리보기로 구성한다. 입력 칸은 제목, 내용, 부가 설명, 표, 담당자다.
- 작성자는 소속 처 섹션에 항목을 만들 수 있다.
- 작성자는 기존 항목에 스스로를 담당자로 할당하거나 해제할 수 있다.
- 한 항목에 여러 명이 할당될 수 있고, 할당된 사람은 그 항목을 수정할 수 있다.
- 한 사람이 항목을 편집하는 동안 그 항목에 "○○○ 편집 중"을 표시하고, 다른 사람은 읽기만 한다.
- 담당자 표기는 할당된 사람의 이름과 직함으로 자동 구성하고, 직접 고쳐 쓸 수 있다.
- 항목 구분은 전주 실적(완료업무), 금주 계획(주간업무), 계속업무 세 가지다.
- 오른쪽 소제목 문구("□ 주간업무" 등)는 처별로 바꿀 수 있다.
- 항목 번호는 순서에 따라 자동으로 붙인다.
- 중간 저장을 할 수 있다.

### 5.3 글자 강조와 표

양식이 깨지지 않는 것이 가장 중요하다. 그래서 작성자가 고를 수 있는 서식을 샘플에 실제로 쓰인 범위로 제한한다.

- 글꼴과 글자 크기는 위치에 따라 고정이며 작성자가 바꿀 수 없다.
- 글자 강조는 굵게와 글자 색(파랑, 빨강) 두 가지만 허용한다.
- 표는 행과 열의 추가와 삭제, 셀 병합, 가운데 정렬을 지원한다.
- 표의 합계 수식(SUM)을 지원한다. 화면에서는 자동으로 계산하고, hwpx에는 수식 필드로 내보낸다.

### 5.4 상태와 검토 흐름

| 상태 | 의미 | 바뀌는 시점 |
|---|---|---|
| 미작성 | 내용이 없다 | 항목 생성 직후 |
| 작성 중 | 저장된 내용이 있다 | 중간 저장 시 자동 반영 |
| 검토 요청 | 상급자의 검토를 기다린다 | 작성자가 검토 요청 시 |
| 수정 요청 | 상급자가 수정을 요구했다 | 검토자가 메시지와 함께 반려 시 |
| 승인 | 상급자가 승인했다 | 검토자가 승인 시 |

- 검토 요청을 하면 그 시점의 작성 버전이 고정된다.
- 검토 요청 뒤에 고치려면 작성자가 "회수"해 작성 중으로 되돌린 뒤 수정한다.
- 수정 요청 메시지는 해당 버전에 붙어 기록된다.
- 처 검토자는 처의 모든 항목이 승인 상태일 때 처 취합본을 상신할 수 있다.
- 실 검토자는 소속 처 섹션이 모두 승인 상태일 때 실 취합본을 상신할 수 있다.
- 검토 순서는 처 → 실 → 본부다. 실이 없는 처는 본부로 바로 간다.
- 검토자는 승인한 뒤에도 다시 수정 요청을 보낼 수 있다.
- 작성자는 승인된 항목도 수정해 다시 검토 요청할 수 있다(재상신).

### 5.5 재상신 때 재검토 범위

승인된 내용이 수정되면 그 위 단계의 승인이 해제된다. 다만 다시 볼 범위는 바뀐 부분으로 좁힌다.

- 처 검토자는 고친 항목만 다시 승인한다.
- 실 검토자와 최종 결정자는 그 처 섹션만 다시 승인한다.
- 다시 검토할 때 바뀐 항목이 표시된다.
- 다른 처의 승인은 유지된다.

### 5.6 현황판

- 처 구성원은 처 안의 항목별 상태를 본다.
- 실 검토자와 최종 결정자는 처별, 실별 상태를 본다.
- 같은 단계의 단위끼리 서로의 상태를 볼 수 있다.
- 검토자는 현황판에서 승인과 수정 요청을 한다.
- 상태가 바뀌면 현황판에 바로 반영된다.

### 5.7 첫 화면과 알림

- 첫 화면은 역할에 맞는 "내가 할 일"을 보여준다. 작성자에게는 수정 요청을 받은 항목, 검토자에게는 검토할 대상이 나온다.
- 메일이나 메신저 알림은 보내지 않는다.

### 5.8 마감

- 기본 마감은 목요일이다.
- 최종 결정자가 마감 일시를 바꿀 수 있다.
- 마감이 지나도 작성과 제출을 막지 않는다. 마감 경과 여부만 표시한다.

### 5.9 주차 이월

- 최종 결정자가 배포하면 다음 주차가 자동으로 열린다.
- 최종 결정자는 배포 전에도 다음 주차를 수동으로 열 수 있다.
- 지난주의 "금주 계획" 항목은 새 주차의 "전주 실적"으로 그대로 복사된다.
- 계속업무 항목은 새 주차에 그대로 유지된다.
- 이월된 항목을 실제 결과에 맞게 고치는 것은 작성자가 한다. 완료 여부를 자동으로 판단하지 않는다.
- 제목과 표의 기간 표기는 주차에 맞춰 자동으로 채운다.
- 첫 주차는 샘플 문서를 한 번 변환해 초기 데이터로 넣는다.

### 5.10 배포와 게시판

- 최종 승인 뒤 최종 결정자가 배포를 실행해야 게시판에 게시된다.
- 배포된 문서를 수정해 다시 배포하면 기존 게시물을 덮어쓰지 않고 새 버전이 쌓인다.
- 게시물 제목은 양식 제목에 차수를 붙인다(예: "기획혁신본부 주간업무 계획 <11.9.~11.13.> 2차").
- 게시판에서는 버전 목록을 보고, 문서를 화면으로 보고, hwpx를 내려받는다.

### 5.11 기록과 통계

- 기록은 검토 요청, 수정 요청, 승인 시점의 버전만 남긴다. 중간 저장은 기록하지 않는다.
- 기록에는 시각, 사람, 내용, 수정 요청 메시지가 들어간다.
- 기록 화면은 항목별 이력을 시간순으로 보여주고, 직전 버전과 달라진 부분을 표시한다.
- 통계는 처별 수정 횟수, 수정 요청 횟수, 마감 준수 여부를 보여준다.

### 5.12 출력

- 전체 문서를 hwpx로 출력한다.
- 처 단위, 실 단위로 본인 소속 범위만 따로 출력할 수 있다.
- hwpx는 샘플 문서를 틀로 삼아 내용만 바꿔 넣는 방식으로 만든다. 글꼴, 표 선, 여백, 로고가 원본 그대로 유지된다.
- 출력물은 기존 양식의 요소를 하나도 빼지 않는다. 표지, 로고, 섹션 표, 소제목, 항목 내 표, 병합 셀, 합계 수식을 모두 포함한다.
- 화면 미리보기는 표 모양, 열 너비, 글자 크기와 굵기를 한글과 맞춘다. 쪽 나눔 위치는 맞추지 않으며 hwpx를 열어 확인한다.

### 5.13 화면 구성

| 메뉴 | 내용 |
|---|---|
| 첫 화면 | 내가 할 일 |
| 작성 | 내 처의 섹션, 칸별 입력과 미리보기 |
| 현황판 | 상태 보기, 검토자의 승인과 수정 요청 |
| 게시판 | 배포된 문서의 버전 목록, 화면 보기, hwpx 내려받기 |
| 기록 | 항목별 이력과 통계 |

## 6. 설계 원칙

시연용이므로 확장 대비는 최소로 한다. 과장님 확인 결과에 따라 바뀔 가능성이 높은 두 가지만 코드가 아니라 데이터로 둔다.

- 조직(본부, 실, 처)과 그 순서.
- 검토 단계와 각 단계의 검토자.

작성 단위는 업무 항목으로 고정한다. 이 구조는 실제 문서에서 나온 것이다.

## 7. 범위

### 7.1 포함

- 주간업무 계획의 작성, 검토, 취합, 배포, 게시, 출력.
- 기획혁신본부 5개 처.

### 7.2 제외

- 비밀번호, SSO 등 실제 인증.
- 조직 관리 화면(조직은 사전 등록).
- 월간 업무계획 흐름(9장 확인 후 반영 여부 결정).
- 기획혁신본부 외 다른 본부.
- 기존 hwp/hwpx 파일을 읽어 들이는 가져오기 기능(첫 주차 샘플은 일회성 변환).
- 메일, 메신저 알림.
- 양식 디자인 자체를 플랫폼에서 바꾸는 기능.
- 실제 운영을 위한 서버 설치, 데이터 보존, 장애 대응.

## 8. 제약

- 내부망 PC에서 사용하는 것을 전제로 한다.
- 출력 형식은 hwpx다.
- 양식의 어떤 요소도 임의로 빼지 않는다.
- 양식이 깨지지 않는 것을 기능 추가보다 우선한다.

## 9. 미확정 사항

아래는 과장님께 확인할 내용이다. 괄호 안은 이 문서가 채택한 가정이다.

### 9.1 구조에 영향을 주는 것

1. 검토는 처 → 실 → 본부 순서인가? (가정: 맞음)
2. 각 단계의 검토자는 처장, 실장, 본부장인가, 별도의 취합 담당자인가? (가정: 각 단계의 장)
3. 처장에게 가기 전에 팀장이 따로 확인하는 절차가 있는가? (가정: 없음)
4. 경영성과처는 본부장에게 바로 올리는가? (가정: 바로 올림)
5. 항목은 담당자가 각자 쓰는가, 처마다 한 명이 모아 쓰는가? (가정: 담당자가 직접 씀)
6. 담당자가 여러 명인 항목은 누가 쓰는가? (가정: 담당자 누구나 수정 가능)
7. 새 주차에서 "금주 계획"을 "전주 실적"으로 그대로 옮기는가, 고쳐 쓰는가? 계속업무는 유지하는가? (가정: 그대로 복사 후 작성자가 고쳐 씀, 계속업무 유지)
8. 기획처의 "□ 월간업무" 소제목은 무슨 의미인가? 별도의 월간 업무계획 문서가 있는가? 있다면 샘플을 받을 수 있는가? (가정: 범위 제외, 소제목 문구만 처별 변경 가능)

### 9.2 세부에 영향을 주는 것

9. 마감은 하나인가, 단계마다 다른가? (가정: 하나)
10. 배포는 본부장이 직접 하는가, 실무자가 대신하는가? (가정: 본부장)
11. 배포 후 수정해 다시 배포하는 일이 실제로 있는가? 수정본 제목은 어떻게 구분하는가? (가정: 있음, 차수 표기)
12. 배포된 문서는 본부 내부만 보는가? (가정: 본부 내부만)
13. 작성 중인 다른 처의 내용을 서로 볼 수 있는가? (가정: 상태만 보이고 내용은 배포 후 열람)
14. 처, 실 단위로만 따로 출력하는 경우가 있는가? (가정: 있음)
15. 본부 전체 인원 명단(이름, 사번, 소속 처, 직급)을 받을 수 있는가? 어렵다면 처별 인원수는? (가정: 검토자만 사전 등록, 나머지는 본인 입력)

## 10. 기술 구성

- 언어: 화면과 서버 모두 TypeScript.
- 서버와 데이터베이스: Bun(내장 웹 서버와 SQLite). 데이터는 파일 하나에 저장한다.
- 화면: React.
- hwpx 생성: 압축 파일 안의 XML을 직접 고쳐서 만든다. 별도 변환 프로그램에 의존하지 않는다.
- 실행 위치: 개발 워크스테이션. 내부망 PC로 옮길지는 과장님 확인 뒤에 정한다.

## 11. 완료 기준

1. 샘플 주차를 플랫폼에 넣고 hwpx로 출력하면 한글에서 원본과 눈으로 구별하기 어렵다.
2. 항목 하나가 작성 → 검토 요청 → 수정 요청 → 재제출 → 처장·실장·본부장 승인 → 배포까지 끝난다.
3. 배포 뒤 항목을 고치면 승인이 풀리고, 다시 배포하면 게시판에 2차가 쌓인다.

출력물은 윈도우 PC의 한글에서 직접 열어 쪽별로 캡처하고 원본과 비교해 확인한다.
