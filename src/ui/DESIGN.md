# 주간업무 계획 화면 기준

## 1. 용도
내부 PC에서 자기 처의 업무를 작성하고, 저장 전에 한글 양식에서 위치와 내용을 확인한다. 정의서 5.1–5.3, 5.12–5.14, 11장이 기준이다.

## 2. 색
LX 누리집의 흰색·옅은 회색 바탕과 가는 중성선을 따른다. 바탕은 #fff, 보조 바탕은 #f8f8f8·#efefef, 본문은 #202321, 보조 글자는 #515751이다. 머리·페이지·구역 구분선은 #d8d8d8 1px이고, 진한 #202321 2px 선은 데이터 목록·통계 표 맨 위에만 둔다. 입력칸·보조 버튼 경계는 #949494 1px로, 흰색 대비 3.03:1을 확보한다.
- LX 포인트는 #009881이다. 고른 머리 메뉴만 LX 누리집의 실제 선택 메뉴색 #006498 글자와 아래 밑줄로 표시하고 숫자 칸의 상태색·흰 글자는 유지한다. 남색은 이 메뉴 표시에만 쓰고 작성 중 상태색 #205b87과는 밑줄·이름·점으로 구분한다.
- 주 버튼은 #007a68 면과 흰 글자다. 흰색 대비는 기본 5.27:1, hover #006b5b는 6.45:1, active #005c4e는 7.95:1이다. LX 원색의 3.62:1보다 짙게 하여 보통 크기 글자의 AA 기준을 지킨다.
- 미작성 #515751, 작성 중 #205b87, 검토 요청 #694693, 수정 요청 #963d30, 승인 #286645를 이름과 함께 유지한다. 동작의 청록색 면과 승인의 초록 글자·점·단계 칸은 모양과 문구로 구분한다.
- 키보드 포커스는 #14589a 2px 외곽선과 2px 간격이다.

머리의 "주간업무 계획" 바로 왼쪽에 틀 문서의 초록 LX 로고(`lx-logo.png`)를 제목 글자 높이(0.9em)로 붙이고 간격 8px, 세로 중앙으로 한 덩어리 간판을 만든다. 로그인 전 머리도 같다. 원본 문서의 색과 서체는 별도로 보존한다.

## 3. 활자
화면은 공식 OFL 배포본 Pretendard GOV의 dynamic-subset 중 400·600·700 woff2 조각과 원본 `unicode-range`를 `fonts/`에 두어 함께 서비스한다. 브라우저는 표시하는 글자에 필요한 조각만 받는다. CDN이나 외부 글꼴 요청 없이 동작하고 OFL 라이선스도 같은 폴더에 둔다. 캐시 없는 작성 화면 첫 로딩의 실제 글꼴 바이트 합계를 캡션에 기록한다. 숫자는 고정폭 숫자다. 크기는 12·14·16·20·26·36px, 굵기는 400·600·700이다. 미리보기·표지의 고딕은 기존 시스템 한글 고딕을 유지하고, 명조 계열도 그대로 둔다. 미리보기는 제목 12pt·본문 11pt·부가 설명 9pt다.

## 4. 배치
간격은 4px 단위. 수평선 하나로 업무 맥락, 항목 선택, 필드, 문서 영역을 구분한다.

Layout: 접속 - 직접 입력과 계정 선택을 모두 노출 → split-screen (https://github.com/changeroa/StyleGallery/blob/main/patterns/split-sidebar/split-screen.md); scroll owner: document; anti-patterns: 좁을 때 필드를 압축하지 않는다.

Layout: 작성 - 입력 대상을 바꾸지 않고 결과를 확인 → supporting-pane (https://github.com/changeroa/StyleGallery/blob/main/patterns/split-sidebar/supporting-pane.md); scroll owner: document, 데스크톱 미리보기만 자체 스크롤; anti-patterns: 세로로 긴 문서 때문에 입력 영역이 밀려나거나 양식 열이 다시 배열되지 않는다.

Layout: 항목 편집 - 선택한 글자·셀 옆에서 서식과 구조 변경 → 기존 작성 supporting-pane 안의 필드와 데이터 표; scroll owner: document, 넓은 편집 표만 가로 스크롤; anti-patterns: 별도의 편집 화면, 도구 때문에 축소되는 양식 열.

Layout: 강조 입력 - 네이티브 입력과 강조 표시를 같은 상자에 겹침 → overlay-stack (기존 항목 편집 패턴 안); scroll owner: input의 가로·textarea의 세로 스크롤, 미러가 추종; anti-patterns: 실제 굵기로 인한 커서·줄바꿈 어긋남.

Layout: 메뉴 숫자 - 내게 남은 동작의 개수를 해당 메뉴 이름 바로 옆에 둔다 → inline count (기존 상태색); scroll owner: 없음; anti-patterns: 별도 할 일 화면, 설명 문구, 0 표시.

Layout: 현황판 - 조직 상태를 비교한 뒤 선택한 처의 제출본을 읽고 결정 → supporting-pane (기존 작성 화면 패턴 재사용); scroll owner: document, 양식만 가로 스크롤; anti-patterns: 조직별 중첩 카드, 검토 페이지 왕복, 내용 없는 승인 버튼.

Layout: 배포 - 현황판 검토 영역 위에 별도 행을 두고 실행 버튼을 오른쪽 끝에 분리한다; scroll owner: document; anti-patterns: 일상 검토 버튼과 함께 배치, 미승인 상태의 배포 버튼.

Layout: 주차 - 제목의 기존 기간 자리에서 작업 범위를 선택 → inline grouping (기존 week 패턴); scroll owner: document; anti-patterns: 날짜 중복, 작성 중 자동 주차 전환.

Layout: 게시판 - 차수 목록과 선택한 제목·다운로드를 남겨 둔 채 고정본을 읽음 → supporting-pane (https://github.com/changeroa/StyleGallery/blob/main/patterns/split-sidebar/supporting-pane.md); scroll owner: 표지와 양식 본문, 높이를 넘는 차수 목록은 별도 스크롤; anti-patterns: 문서 끝에서 차수를 잃거나 좁은 열에 양식 비율이 깨지는 배치.

Layout: 기록 - 처 전체·항목의 단계를 고르며 한 제출본을 확인 → list-detail (기존 supporting-pane 패턴); scroll owner: 높이가 제한된 왼쪽 목록과 오른쪽 상세 각각, 양식만 내부 가로 스크롤; anti-patterns: 모든 기록 펼침, 단계 수에 따라 늘어나는 페이지, 통계와 기록의 동시 노출.

Layout: 항목 기록 팝업 - 작성·검토 위치를 유지하며 단계 확인 → list-detail (기록과 공용); scroll owner: 가운데 dialog의 좁은 목록과 상세 각각; anti-patterns: 양식 중복, 배경 스크롤, 팝업 열기로 편집 상태 소실. 860px 아래는 목록 위·상세 아래.

## 5. 화면과 동작
- 접속: 주 동작은 접속. 이름·사번 → 최초 등록용 소속 처·직급 → 조직별 계정 목록. 목록 선택만으로 접속한다.
- 작성: 현재 처·주차 → 구분과 번호·상태 → 선택한 항목과 미리보기. 읽기 상태의 주 동작은 본인 할당, 편집 중 주 동작은 중간 저장이다.
- 필수: 네 메뉴와 할 일 숫자, 역할·소속·이름, 계정 전환, 세 구분, 추가, 잠금·할당 해제, 제목·내용·부가 설명·표·담당자, 처 소제목, 저장 피드백, 주차 전체 다운로드.
- 작성 검토: 수정 요청 항목의 목록·편집 영역은 상태색 띠로 두른다. 항목 아래 공통 접이식 카드에 보낸 사람·시각·메시지·검토 단위를 표시하고 수정 요청 중 기본 펼침. 두 번째 제출부터 검토 요청 옆에 수정 사유(선택)를 두며 제출한 사유도 같은 카드로 표시한다. 저장하지 않은 변경은 제출 시 먼저 저장하며 빈 사유는 확인 없이 제출한다. 검토 중에는 읽기와 회수만, 승인 후에도 편집·사유 입력을 유지한다.
- 메뉴: 게시판·작성·현황판·기록 순서이고 접속 직후는 게시판이다. 작성 옆에는 내가 처리할 수정 요청 개수를 수정 요청색, 현황판 옆에는 내가 검토·상신할 대상 개수를 검토 요청색 칸에 흰 고정폭 숫자로 둔다. 0이면 칸을 두지 않는다. 현황판은 내 동작이 남은 처를 먼저 연다.
- 목록 선택: 작성 업무 항목·게시판 배포본·현황판 조직·기록 단계의 고른 줄은 왼쪽 #009881 3px 띠와 옅은 회색 바탕으로 표시한다. 선택 전후 내용의 위치와 행 너비를 유지하고, 상태색과 포커스 외곽선은 보존한다.
- 현황판: 실제 조직별 상태 → 선택한 처와 항목의 제출 내용·수정 사유 카드 → 서버가 허용한 승인·수정 요청·취합본 상신. 수정 요청·수정 사유는 같은 가는 선 접이식 카드에 상태색·문구만 달리 쓴다. 수정 요청은 메시지 필수, 섹션은 대상 항목도 필수. 승인할 때는 승인이 주 동작, 상신할 수 있을 때는 상신이 주 동작이다.
- 항목 편집: 주 동작은 중간 저장. 선택한 필드·셀 → 해당 범위의 동작 → 미리보기 순서. 굵게·파랑·빨강 토글, 표 추가·삭제, 행·열 추가·삭제, 셀 텍스트·병합·나누기·정렬·합계를 지원한다. 선택 전체에 적용된 토글은 채운 면으로 표시한다. 읽기 상태에는 편집 도구를 두지 않는다.
- 다른 편집자의 잠금만 가는 색 테두리와 원형 머리글자로 표시한다. 저장 버튼 옆 상태점은 저장됨·미저장을 구분한다. 담당 해제는 폼 끝에 분리하고 확인을 거친다.
- 처 섹션 상태명 옆에 실제 검토 단계별 색 칸을 둔다. 각 칸에 처·실·본부 단계명을 쓰고, 도달하지 않은 단계는 연회색이다.
- 강조 입력: 제목·내용·부가 설명 안에 문서색 강조를 표시한다. 네이티브 입력·선택·IME를 유지하고 미러의 굵기만 같은 색 text-shadow로 폭을 보존한다. 강조 버튼은 적용할 굵기·색을 표시하고 선택 범위가 없으면 흐리게 비활성화한다. 읽기 상태도 강조를 표시한다.
- 입력 도구: 수정 요청 카드 바로 아래 제목 입력칸을 두고 그 아래 공용 도구줄에는 현재 필드의 강조 → 가는 구분선 → ○·→「」‘□·내용 머리말 버튼을 둔다. 좁으면 그룹 단위로 줄바꿈한다. 삽입은 커서·선택 위치에 적용하고, 처음 누르면 제목 끝에 넣는다. 빈 「」는 사이에 커서, 선택 문구는 감싸고 뒤에 커서. 삽입 버튼은 편집 중 항상 활성화하며 읽기 상태에는 도구를 두지 않는다.
- 제외: 미구현 메뉴 화면, 글꼴·크기 선택, 머리 LX 로고 외의 장식용 로고·타일·배지.
- 본부장: 작업 주차 → 최종 승인 대기 처 또는 배포 제목·차수 → 같은 자리에서 배포 확인. 다음 주차 수동 열기는 보조 동작이다. 다른 역할에는 이 행을 두지 않는다.
- 게시판: 선택한 배포본 열람이 주 동작이다. 최신 버전부터 제목·차수, 배포 일시·배포자 → 원본 표지와 처 순서의 고정 문서 → 그 버전의 HWPX 다운로드. 통계, 작업 중 문서, 별도 검색·편집 기능은 제외한다.
- 주차: 현재/이전과 기간을 함께 표시한다. 이전 주차를 고르면 작성·검토·재배포 모두 선택한 범위를 유지한다.
- 기록: 주 동작은 단계 선택. 기록(기본)·통계 탭. 처 선택 → 처 전체 단계·세 구분의 항목 → 한국시간 날짜·시각을 포함한 최신순 단계 목록과 고른 상세 하나. 선택한 단계는 목록 안에 자동 노출하고 항목 제목을 고정한다. 상세는 상태·사람·시각·차수, 공통 수정 요청·사유 카드, 직전 대비 삭제·추가, 제출 내용, 같은 버전의 항목 양식 순서. 제출 표는 가로만 스크롤한다. 처 전체 상세는 지목 항목을 해당 단계로 연결한다. 빈 상태는 문장. 통계 표의 수치·기준은 유지한다.
- 항목 기록 팝업: 작성·현황판·양식 제목에서 열고 현재 편집·잠금을 유지한다. 단계 목록은 동작·날짜 한 줄 너비, 상세는 기록과 공용이며 양식은 생략한다. Esc·닫기 뒤 원래 버튼에 포커스. 기록에서 양식으로 보기는 같은 항목·단계를 열며 기존 이탈 확인을 따른다.
- 마감: 주차 옆에 한국시간과 마감 전/경과를 함께 둔다. 경과는 수정 요청과 같은 경고색을 쓰며 작업을 막지 않는다. 본부장만 현황판에서 주차 마감을 변경한다.
- 작성 출력: 미리보기 오른쪽의 ↓ HWPX 버튼으로 전체 주차·권한 있는 상위 실·현재 처의 다운로드 목록을 연다.

## 6. 구성 요소
브라우저 기본 button·input·select·textarea·table을 사용한다. 상태·버튼·입력은 공통 CSS, 원본 표는 별도 네임스페이스. 조직과 역할의 소속 관계는 API 응답을 따른다.

## 7. 표면
흰 머리 아래에만 `0 2px 4px rgb(32 35 33 / .05)`의 옅은 그림자 한 줄을 둔다. 둥근 모서리·장식·애니메이션은 쓰지 않는다. 입력 미러의 폭 중립 굵기에 text-shadow를 허용한다. 주간 양식의 표 머리 음영은 원본에 맞추고, 문서 영역의 색·선·서체는 화면의 LX 톤과 분리해 보존한다. 제품은 5.14의 흰 종이색 체계를 고정 사용한다.

## 8. 검증 대상
키보드 접근·포커스·명도 대비, 저장 전 이탈 확인, 잠금 소유권, 실시간 미리보기와 출력 보존, 좁은 화면의 표 가독성. 기준선은 UI가 없던 서버 안내 페이지이며, 사용감의 근거는 U2 인계서의 실제 화면 캡처에 둔다.
